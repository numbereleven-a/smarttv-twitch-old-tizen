# Twitch Old Tizen

Предлагаемое имя проекта: `smarttv-twitch-old-tizen`.

## Краткое описание

Добавлено воспроизведение Twitch-каналов с новым HLS/fMP4 на Samsung KU6000 с Tizen 2.4. Приложение выбирает H.264/AAC до 1080p и преобразует контейнер прямо на телевизоре, разделяя звук и видео для MSE. Перекодирование, внешний сервер, постоянно включённый компьютер и NaCl не нужны. Исправлены несовместимости JavaScript старого Tizen, отображение видео, зависший индикатор загрузки и обработка некорректных сообщений чата.

Поддержка каналов с включённым 1440p означает просмотр их доступных 720p/1080p-версий. Воспроизведение самого 1440p эта сборка не заявляет.

## Что изменено подробно

Основа — smarttv-twitch и вариант HLS/MSE из PR #328, локальная исходная ревизия `b1d94758fa8bc851dfaa76cd7a755073645f8869`. Авторство и лицензии исходного проекта сохраняются.

### Формат потока и выбор качества

У исследованных каналов младшие качества также передаются через HLS/fMP4 с отдельным init-сегментом. Поэтому понижение разрешения само по себе не возвращает прежний MPEG-TS. Для просмотра используется hls.js 1.6.5 и MediaSource вместо нативного HLS-разбора AVPlay.

Список качеств ограничен AVC/H.264 с шириной не более 1920 и высотой не более 1080. Начальное предпочтение — 720p. Убрана преждевременная загрузка общего мастер-плейлиста плеером: загружается выбранный вариант.

### Преобразование fMP4 на телевизоре

Добавлены `Fmp4TrackIsolation.js` и `LegacyFmp4Buffers.js`:

- Выделяются описания аудио- и видеодорожек в init-сегменте.
- Для звука и видео создаются отдельные MSE SourceBuffer.
- Удаляются служебные структуры другой дорожки.
- В каждом фрагменте оставляются только данные выбранной дорожки; пересчитываются размеры контейнеров и смещения к данным пакетов.
- 32-битные tfdt переводятся в 64-битную форму без изменения значения времени.
- Сохраняются сжатые H.264/AAC-пакеты: декодирование выполняет телевизор, повторного кодирования нет.
- Учёт потоков фрагмента в hls.js согласован с двумя отдельными буферами, включая ожидание завершения добавления данных.

Это специализированная обработка проверенного формата Twitch, а не универсальный MP4-конвертер. Неподдерживаемые варианты адресации и структуры фрагментов отклоняются. Расширенные размеры MP4-блоков и зашифрованные потоки не заявлены как поддерживаемые.

### Совместимость JavaScript и интерфейс

- Добавлены Promise-полифилл 8.3.0 с лицензией и совместимые реализации Array/String.includes.
- Локальное использование WeakSet в hls.js заменено массивом.
- Учтено, что старый video.play() может возвращать undefined, а не Promise.
- Web Worker отключён: основной контекст содержит необходимые полифиллы.
- Исправлено позиционирование HTML video и показ при готовности кадров/движении воспроизведения.
- Индикатор загрузки скрывается при фактическом продвижении воспроизведения с готовыми данными.
- Добавлены проверки пустых данных emotes и нестрокового system-msg в чате.
- Диагностика воспроизведения пишется в консоль, не закрывая изображение экранным окном.

## На чём проверено

| Параметр | Подтверждённая конфигурация |
|---|---|
| Телевизор | Samsung UE50KU6000, серия KU6000, 2016 год |
| Tizen | 2.4.0 |
| Прошивка | T-JZL6DEUC-1260.1, по данным владельца |
| Проверка прямого эфира | 18 сентября 2026 года |
| Каналы | rdulive и silvername |
| Результат | Владелец подтвердил картинку и звук, переключение качества и поиск другого канала |
| Сеть воспроизведения | Прямое получение потока телевизором, без сервера преобразования на ПК |

720p60 использовалось в последовательных проверках живого эфира. Владелец подтвердил переключение качеств, но отдельный протокол длительного автономного теста каждого качества, включая 1080p60, не оформлялся. Локальный двухсекундный образец 1080p60 воспроизводился на ТВ через MSE со звуком. Более ранний тест 720p/1080p через ПК с MPEG-TS был только диагностикой и не является доказательством автономного живого 1080p-теста.

На ПК проверено сохранение всех пакетов на двух образцах: 120 видеопакетов и 94 аудиопакета в каждом, совпадение SHA256 полезных данных, PTS/DTS, размеров и длительностей. Проверены обработка событий hls.js, синтаксис изменённого JavaScript и сборка/подписание WGT. Эти проверки дополняют испытания на ТВ, но не заменяют их.

## Требования и границы совместимости

Для воспроизведения необходимы:

1. Samsung TV на Tizen с работающим MediaSource и отдельными MP4 SourceBuffer для H.264 и AAC.
2. Аппаратный декодер, способный воспроизводить выбранное разрешение, профиль H.264 и частоту кадров, а также AAC.
3. Доступ телевизора к API и CDN Twitch; пропускная способность с запасом относительно битрейта выбранного качества.
4. Возможность установить подписанное Tizen Web-приложение.

Минимальная **проверенная** платформа — указанная Tizen 2.4/KU6000. В манифесте стоит required_version=2.3, но это порог установки, не доказательство работы на Tizen 2.3. Другие модели 2016 года, более старые и более новые модели отдельно не проверялись. Наличие MediaSource или положительный isTypeSupported само по себе не гарантирует воспроизведение.

Samsung описывает MSE и ограничения видео для моделей 2016 года в своей документации; индивидуальная проверка модели всё равно нужна. Многими часами непрерывного просмотра, восстановлением после сна/обрыва сети, рекламными вставками, VOD, клипами и авторизацией текущая сборка пока не аттестована.

## Установка и повседневное использование

Название в списке приложений: **Twitch Old Tizen**. Используется штатная прямоугольная иконка проекта для старых телевизоров: SmartTV client for Twitch. Это отдельная установленная сборка, не публикация в магазине Samsung. Ищите её в Apps/списке установленных приложений; закрепление на домашней панели зависит от интерфейса телевизора.

Для установки использованы Developer Mode, Tizen Studio, Samsung Certificate Extension, авторский сертификат и сертификат дистрибьютора с DUID телевизора. Для другого устройства потребуется подходящая подпись с его DUID: текущий подписанный WGT не следует считать универсальным установщиком. Исходный author-сертификат следует сохранить для дальнейших обновлений.

При переименовании сохранены app ID `KuHlsTest1.SmartTV` и package ID `KuHlsTest1`: обновляется текущая тестовая установка. Отдельная установка оригинального приложения не заменяется.

Штатный механизм входа оригинального проекта сохранён: добавить пользователя, затем выполнить предлагаемую приложением процедуру получения и ввода ключа авторизации. Владелец подтвердил, что авторизация в Twitch Old Tizen работает. Состояние уже сохранённой авторизации при переустановке или смене подписанного пакета зависит от локального хранилища ТВ; обновление приложения использует тот же app ID.
